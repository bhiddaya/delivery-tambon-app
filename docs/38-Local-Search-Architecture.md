## ๑ สรุปจุดยืน

### เห็นด้วย

| ข้อเสนอ | เหตุผลที่เห็นด้วย |
|---|---|
| `tambon_id` เป็นแกนแบ่งข้อมูล ไม่แยก Supabase project ต่อตำบล | ตรงกับที่สร้างไว้แล้ว และเป็นทางที่ย้อนกลับได้ถ้าคิดผิด |

## ๒ สิ่งที่มีอยู่แล้วจริง — ตรวจแล้ว ไม่ใช่ความจำ

โครงสร้างที่ต้องใช้ทำ Local Search **มีอยู่แล้วเกือบครบ** สิ่งที่ขาดคือข้อมูล ไม่ใช่ตาราง

| ตาราง | สิ่งที่มี | จำนวนแถวจริง | สรุป |
|---|---|---:|---|
| `tambons` | `delivery_fee_base`, `delivery_fee_per_km`, `is_active` | 1 | สูตรค่าส่งตามระยะ **มีอยู่แล้ว** |
| `merchants` | `lat`, `lng`, `is_open`, `category`, `tambon_id` | 3 | โครงพิกัดครบ — แต่ **มีแค่ 1 ร้านที่กรอกพิกัด และร้านนั้นไม่มีสินค้าเลย** |
| `menu_items` | `name`, `price`, `photo_url`, `is_available`, `is_hidden` | 17 | ไม่มีหมวดหมู่ระดับสินค้า |
| `orders` | `pickup_lat/lng`, `dropoff_lat/lng`, `delivery_fee` | 36 (ทดสอบทั้งหมด) | โครงพร้อม |
| `places` | `tambon_id`, `category`, `name`, `lat`, `lng`, `phone` | **0** | ทะเบียนสถานที่ในชุมชน — สร้างไว้ ไม่เคยใช้ |
| `tambon_profiles` | `population`, `households`, `villages`, `area_sqkm` | 1 แถว แต่**ค่าว่างทั้งหมด** | ยังไม่รู้ขนาดตำบลตัวเอง |
| `merchant_rankings` / `driver_rankings` | `avg_score`, `rating_count` | มุมมองพร้อมใช้ | รองรับ "ร้านยอดนิยม" ได้แล้ว |
| `ai_conversations` | `line_user_id`, `role`, `content` | 100 ข้อความ จาก **1 คน** หยุดเมื่อ 5 ก.ย. | มีคนใช้จริงคนเดียว |
| `pending_menu_items` | ร้านเพิ่มเมนูผ่านแชท | **0** | สร้างไว้ ไม่เคยใช้ |
| `job_seekers` | ทะเบียนหางานในตำบล | **0** | สร้างไว้ ไม่เคยใช้ |

**ข้อสรุปที่สำคัญที่สุดของเอกสารนี้:** วิสัยทัศน์ "ฐานข้อมูลเศรษฐกิจท้องถิ่น" ถูกสร้างเป็นตารางไว้แล้วหลายส่วน (`places`, `job_seekers`, `pending_menu_items`) และ **ทุกส่วนมีศูนย์แถว** ปัญหาของระบบตอนนี้ไม่ใช่สถาปัตยกรรม แต่คือ *ไม่มีอะไรอยู่ข้างใน*

## ๓ ตัวเลขที่ควรใช้วางแผน

ประเทศไทยมีราว 7,255 ตำบล ประชากรราว 66 ล้านคน → **เฉลี่ยตำบลละประมาณ 9,000 คน** หรือราว 2,500–3,000 ครัวเรือน

ในตำบลขนาดนั้น ร้านที่จะสมัครเข้าระบบส่งอาหารจริง ๆ — ร้านที่มีคนทำอาหารประจำ เปิดสม่ำเสมอ และยอมรับออร์เดอร์ออนไลน์ — ตามประสบการณ์ของแพลตฟอร์มอื่นในพื้นที่ชนบท อยู่ที่หลัก **สิบต้น ๆ ถึงไม่กี่สิบร้าน** ไม่ใช่ 100–500 ร้าน

| | ประมาณการที่เสนอมา | ที่ควรใช้วางแผน |
|---|---:|---:|
| ร้าน/ตำบล | 100–500 | **10–40** |
| สินค้า/ตำบล | 3,000–20,000 | **200–1,500** |
| ออร์เดอร์/วัน/ตำบล | 55–274 | **5–30** (ถ้าไปได้ดี) |

**ทำไมเรื่องนี้สำคัญ:** ถ้าเชื่อว่าจะมี 500 ร้าน จะออกแบบ PostGIS, search index, ranking algorithm, cache layer — ทั้งหมดนี้ไม่จำเป็นที่ 20 ร้าน และการสร้างมันขึ้นมาก่อนคือการใช้เวลาที่ควรเอาไปชวนร้านมาเปิด

**สถานะจริงวันนี้: 1 ร้านที่ใช้งานได้จริง (ใจสุข, 16 รายการ) และไม่มีอาหารปรุงสุกสักรายการ**

ตัวเลข 100–500 ร้านจะเป็นจริงได้ก็ต่อเมื่อระบบครอบคลุมมากกว่าอาหาร — ซึ่งเป็นวิสัยทัศน์ที่ถูก และตาราง `places` รองรับไว้แล้ว แต่นั่นคือคนละเรื่องกับ Delivery

## ๕ สิ่งที่ต้องเพิ่มในฐานข้อมูล — และสิ่งที่ไม่ต้องเพิ่ม

### ต้องเพิ่ม (เรียงตามความจำเป็น)

**๑. สมุดที่อยู่ลูกค้า** — ยังไม่มีตารางนี้เลย ตอนนี้ลูกค้าต้องปักหมุดใหม่ทุกครั้งที่สั่ง

```
customer_addresses
  profile_id · label ("บ้าน"/"ที่ทำงาน") · address · lat · lng · is_default
```

เหตุผลที่แท้จริงที่ต้องเก็บพิกัด **ไม่ใช่เพื่อจัดอันดับร้าน แต่เพื่อคิดค่าส่ง** — `tambons.delivery_fee_per_km` มีอยู่แล้ว ถ้าไม่รู้ปลายทาง สูตรนั้นใช้ไม่ได้ นี่คือเหตุผลที่หนักแน่นพอจะขอตำแหน่งจากลูกค้า

**๒. เวลาทำการของร้าน** — `is_open` เป็นสวิตช์ที่ร้านต้องกดเอง ซึ่งร้านในชนบทจะลืมกดปิด ทำให้ลูกค้าสั่งไปแล้วไม่มีคนรับ

```
merchant_hours
  merchant_id · weekday (0-6) · open_time · close_time
```

**๓. รัศมีส่งของร้าน** — `merchants.delivery_radius_km` ร้านหลายร้านไม่ส่งข้ามตำบล หรือส่งเฉพาะรอบ ๆ

**๔. หมวดหมู่ระดับสินค้า** — `menu_items.category` เพื่อรองรับการค้นแบบ "ก๋วยเตี๋ยว" "ของหวาน" ที่ชื่อสินค้าไม่ได้มีคำนั้น

### ไม่ต้องเพิ่ม

**PostGIS** — สูตร Haversine เขียนใน SQL ธรรมดาได้ แม่นพอที่ระยะไม่เกิน 20 กม. และที่จำนวนร้านหลักสิบ การสแกนทั้งตำบลเร็วกว่าการใช้ spatial index อยู่แล้ว ติดตั้งเมื่อร้านต่อตำบลเกินหลักร้อยจริง ๆ

**Search index / full-text** — ภาษาไทยไม่มีช่องว่างระหว่างคำ Postgres จึงตัดคำไทยไม่ได้ `to_tsvector('thai', ...)` ไม่มีในมาตรฐาน วิธีที่ใช้ได้จริงคือ `ilike '%คำ%'` และเพิ่ม `pg_trgm` เมื่อต้องการเผื่อพิมพ์ผิด

**ผลข้างเคียงที่ต้องยอมรับ:** ค้น "ชา" จะเจอ "ถ่านไบโอ**ชา**ร์" ด้วย — ที่ขนาดนี้ยังไม่คุ้มจะแก้ ทางแก้ในอนาคตคือตารางคำพ้อง ไม่ใช่ full-text

## ๖ เส้นทางคำขอ — ข้อขัดแย้งที่ยังไม่ตัดสิน

ข้อเสนอที่ได้รับให้ n8n อยู่กลางทาง:

```
LINE OA → n8n (ตีความคำค้น + query Supabase + คำนวณระยะ) → LINE OA
```

**ข้อโต้แย้ง — จากสิ่งที่เกิดขึ้นจริงกับระบบนี้ ไม่ใช่หลักการลอย ๆ**

`My workflow 3` ทำหน้าที่นี้อยู่แล้วในวันนี้ และผลคือ:

- โปรไฟล์ ๑๒ ตัวที่ **ไม่มีบัญชี auth** — เจ้าของ LINE เหล่านั้นล็อกอินเข้าระบบไม่ได้ตลอดไป จนกว่าจะล้างค่าออก
- ออร์เดอร์ ๓๒ ใบจาก ๓๔ ใบ **ราคา 0.00 บาท** — ไม่ผ่านสูตรค่าส่ง ไม่มีไรเดอร์รับ
- ไม่มี error ให้ใครเห็นสักครั้ง เพราะ n8n ถือ service key จึงเขียนผ่าน RLS ได้หมด

สาเหตุเชิงโครงสร้าง: n8n ต้องรู้ชื่อคอลัมน์เอง ไม่มี type check ไม่มี build error และถือกุญแจที่ข้ามการตรวจสิทธิ์ทั้งหมด เมื่อ schema เปลี่ยน มันพังเงียบ

**ข้อเสนอทดแทน — โครงเดิม เปลี่ยนผู้ลงมือ**

```
LINE OA → /api/line/webhook (ในแอป) → search_menu() → LINE OA → LIFF → PWA
```

n8n ยังอยู่ แต่เป็น **นาฬิกาปลุก** — ยิง `notify` ตามเวลา ถือแค่ `NOTIFY_SECRET` ไม่แตะตาราง ตรงกับกฎในเอกสาร ๓๐ ที่ตกลงกันไว้แล้วว่า *"n8n คือกาว ไม่ใช่แกน"* และตรงกับตารางในเอกสารนั้นที่ระบุชัดว่า **ห้าม n8n สร้าง/แก้ออร์เดอร์ และห้ามคิดค่าส่ง**

**เรื่องที่ต้องรู้ก่อนสับสวิตช์:** `/api/line/webhook` ตอบ `configured:false` แปลว่า Webhook URL ของ LINE OA **ไม่ได้ชี้มาที่แอป** เกือบแน่นอนว่าชี้ไปที่ n8n การย้ายจึงเป็นการตัดช่องทางที่ 94% ของการใช้งานจริงวิ่งผ่านอยู่ — **ต้องสร้างของแทนให้เสร็จและทดสอบคู่ขนานก่อน ห้ามปิดก่อน**

## ๗ ลำดับที่เสนอ

| เฟส | ทำอะไร | เงื่อนไขที่ต้องผ่านก่อนขึ้นเฟสถัดไป |
|---|---|---|
| **0 — วันนี้** | ชวนร้านอาหารปรุงสุกในบุ่งไหมมาลง 3–5 ร้าน · กรอกพิกัดให้ทุกร้าน · รวมร้าน "ใจสุข" ที่ซ้ำกัน | มีอาหารให้ค้นเจอจริง |
| **1** | ค้นชื่อสินค้า + ค้นชื่อร้านในแชท → เปิด PWA → **สั่งจริง 1 ออร์เดอร์ที่มีราคาและมีไรเดอร์รับ** | วงจรครบหนึ่งรอบ |
| **2** | GPS + ค่าส่งตามระยะ + สมุดที่อยู่ + เวลาทำการ + ตัวกรองราคา | ลูกค้าสั่งซ้ำเองโดยไม่มีใครสอน |
| **3** | หมวดหมู่ · ร้านยอดนิยม · "สั่งเหมือนครั้งที่แล้ว" · ขยาย `places` | มีออร์เดอร์ต่อเนื่องพอให้อันดับมีความหมาย |
| **4** | ภาษาธรรมชาติด้วย AI ครอบด้านหน้า | ทุกอย่างข้างบนนิ่งแล้ว |

**เฟส 0 เป็นงานของเจ้าของโครงการ ไม่ใช่งานเขียนโค้ด** และเป็นตัวตัดสินว่าทั้งหมดนี้มีความหมายหรือไม่ ระบบค้นหาอาหารที่ไม่มีอาหารให้ค้น จะทำให้คนที่ลองแล้วไม่กลับมาอีก
