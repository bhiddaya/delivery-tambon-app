# Delivery PWA: frontend ใหม่จากฐานข้อมูลเดิม

ขอบเขตตามคำสั่งเจ้าของ 4 ตุลาคม 2569: สร้างตัวเว็บ Delivery ใหม่ให้สวย อ่านง่าย ข้อมูลครบ เป็น PWA และส่งขึ้น GitHub/Vercel
งานนี้ต่อจากหน้าเข้าเว็บ/PWA ฉบับแรก แล้วเปลี่ยนหน้าหลักที่ผู้ใช้ทำงานจริงด้วย

## หน้าที่สร้างใหม่

| เส้นทาง | หน้าที่ |
| --- | --- |
| `/delivery` | พื้นที่บริการและรายชื่อร้านที่เปิด อ่านเฉพาะคอลัมน์สาธารณะ |
| `/customer` | ร้านและเมนูจริงในตำบลบัญชี ค้นหาชื่อร้าน/เมนู กรองหมวด และดูงานที่กำลังดำเนินการ |
| `/customer/merchants/[id]` | เมนู รูป ราคา เพิ่มลดจำนวน รวมค่าสินค้าจากราคาล่าสุด ตรวจรายการ แล้วเปิด LINE ให้ผู้ใช้ส่งเอง |
| `/customer/orders` | กรองสถานะและช่วงเวลา ดูความคืบหน้า รายการสินค้า จุดรับ/ส่ง และขั้นตอนสลิปของระบบเดิม |
| `/customer/parcel`, `/customer/ride` | ฟอร์มจุดรับ/ส่ง รายละเอียด และตรวจข้อมูลก่อนยืนยันบริการผ่าน LINE |
| `/merchant` | ข้อมูลร้าน เปิด/ปิด เมนู ราคา รูป แจ้งหมด พักขาย/นำกลับ โดยเก็บประวัติออเดอร์ |
| `/merchant/orders` | รายการเข้าร้านและหมายเหตุ กรองเวลา/สถานะ ดูรายละเอียดการส่ง |
| `/driver` | พร้อมรับงาน ส่งตำแหน่งเมื่อผู้ใช้กด รับงานโดยตรวจสถานะล่าสุด ยืนยันส่งสำเร็จ และอ่านยอดรอโอนจริง |
| `/admin` | ภาพรวมตามสิทธิ์ตำบล กรอง 1/7/30 วัน เรื่องค้าง สถานะออเดอร์ และความพร้อมร้าน/ไรเดอร์ |

โค้ดหน้าใหม่อยู่ใน `src/rebuilt/` และใช้ AppShell ใหม่: sidebar บนจอใหญ่ เมนูล่าง/เมนู dialog บนมือถือ ข้อมูลผู้ใช้และสถานะออฟไลน์
AuthFrame และ UI กลางปรับเพื่อให้อ่านง่าย ช่องกรอกขนาดเหมาะกับมือถือ และซูมได้
หน้าบัญชี สมัคร เข้าสู่ระบบ รายรับ และงานปฏิบัติการย่อยของตัวแทนยังใช้ flow/backend เดิมภายใต้หน้าตาและโครงนำทางใหม่

## ข้อมูลและสิทธิ์

ใช้ Supabase project เดิม ผ่าน browser/server client ที่ผูก session และ RLS เดิม
ไม่เปลี่ยน schema, policy, credential, auth, LINE/n8n, DNS หรือบัญชีรับเงิน
ไม่รวมกุญแจ service role ในหน้าเว็บ ไม่เพิ่มสิทธิ์อ่านเมนูให้ anonymous และไม่คัดข้อมูลผู้ใช้ลง source
กรองตำบลและสถานะข้อมูลทดสอบตามบัญชี การอ่านล้มเหลวแสดงข้อผิดพลาด/ลองอีกครั้ง ไม่แสดง 0 เป็นผลสำเร็จ

ตรวจ read-only ด้วย role `anon` วันที่ 4 ต.ค.: อ่านพื้นที่ได้ 3 ตำบล ร้านเปิด 6 ร้าน แต่เมนูเห็น 0 รายการตาม policy ปัจจุบัน
ทั้ง 3 ตำบลยังไม่มี `delivery_fee_base` จึงไม่แสดงราคาส่งที่เดาเอง
หน้าใหม่ให้จัดรายการ/ขอบริการและยืนยันราคาใน LINE; การกดตรวจรายการไม่ insert ออเดอร์
ระบบฐานข้อมูลปัจจุบันยังไม่มี RPC สร้าง food order + order_items ใน transaction เดียว และ trigger แจ้งงานเริ่มตอน insert orders
การเปิด checkout เว็บอัตโนมัติต้องเป็นงาน backend ที่ได้รับอนุมัติ พร้อมตั้งค่าราคาจริงและทดสอบแยก

Driver UI ไม่เขียน today_jobs/today_earn หรือ ledger โดยตรง
การรับงานตรวจ pending + driver_id ว่าง และต้องได้แถวตอบกลับ จึงไม่รายงานสำเร็จเมื่อมีคนรับไปก่อน
การเลื่อนสถานะตรวจ driver_id และสถานะเดิม พร้อมยืนยันก่อน delivered
ยอดรอโอนอ่าน settlements จริง ไม่ใช้ค่าประมาณจากหน้าเว็บเป็นยอดเงิน

## PWA

ใช้ manifest, ไอคอน, ปุ่มติดตั้ง และ service worker ที่เตรียมไว้ในฉบับแรก ดู `45-DELIVERY-PWA.md`
เก็บเฉพาะ shell/static assets; ไม่ cache HTML ออเดอร์/บัญชี, Supabase responses, API หรือ mutation
เมื่อออฟไลน์แสดงหน้าแจ้งสถานะ ไม่มีการสั่งออฟไลน์หรือส่ง push notification ใหม่

## ตรวจซอร์สและทดสอบ

```sh
npm ci
npm run build
node --experimental-strip-types --test tests/delivery-pwa.test.mjs tests/rebuilt-order.test.mjs
```

ทดสอบ interaction แบบ offline DOM โดยติดตั้งเครื่องมือ QA แยกจาก dependency ของเว็บ:

```sh
npm install --prefix /tmp/delivery-ui-qa --no-audit --no-fund --save-exact esbuild@0.25.12 jsdom@26.1.0
DELIVERY_QA_TOOLS=/tmp/delivery-ui-qa node tests/rebuilt-ui.test.mjs
```

ชุดทดสอบใช้ข้อมูลจำลองและแทนที่ Supabase, session, navigation ทั้งหมด ไม่ส่งข้อมูลออกเครือข่าย
ครอบคลุมค้นหา/ล้างตัวกรอง เพิ่มลดสินค้า ยอดปัจจุบัน ค่าส่งว่าง ตรวจรายการและ LINE link ร้านปิด
กรอง/ขยายออเดอร์ แก้ความพร้อม/พักเมนู/เพิ่มเมนู กรณีมีคนรับงานก่อน ยืนยัน delivered โดยไม่แก้ counter เงิน
ตรวจ retry, warning การตั้งค่าตำบล, ขอบริการ และเปิด/ปิดเมนูมือถือ
ชุด unit/PWA มี 13 tests รวมการป้องกัน cache ข้อมูลส่วนตัวและค่า quantity/price ที่ไม่ถูกต้อง

ตรวจ lint ไฟล์ที่เปลี่ยนและ scan รายการ source ก่อนส่ง โดยไม่รวม `.env*`, private keys, `.git`, node_modules หรือ runtime
Full-repo lint ยังมี 3 errors เดิมใน `wip/` และ 4 warnings เดิม ไม่ได้ deploy โค้ด wip

ข้อจำกัด: DOM จำลองไม่ยืนยัน pixel layout หรือการติดตั้ง PWA จริง เบราว์เซอร์ production ถูกปฏิเสธสิทธิ์ระหว่างงานนี้
ผล build/local HTTP/DOM/Vercel CI ต้องรายงานแยกจากการล็อกอินจริง LINE E2E การชำระเงิน และมือถือจริง
ไม่สร้างออเดอร์ ส่ง LINE แนบสลิป อัปโหลดรูป หรือแก้ข้อมูลธุรกิจจริงในการทดสอบ
