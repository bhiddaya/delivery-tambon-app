# ออกแบบ: ตอบกลับเป็นเสียงพูด (LINE OA บวรไทย)

สถานะ: **ร่าง รอการอนุมัติ** ยังไม่ได้สร้าง แก้ไข หรือ publish อะไร
วันที่: 2026-11-19

## เจตนา
เมื่อผู้ใช้ **พูด** (ส่งข้อความเสียง) มาที่ OA บวรไทย บอทจะตอบเป็นเสียงพูดภาษาไทยที่ฟังเหมือนคนคุย สุภาพ เป็นกันเอง และส่งข้อความเต็มตามไปด้วย
เป้าหมายคือให้ฟังเป็นธรรมชาติ โดยไม่มีค่าใช้จ่ายรายเดือนเพิ่ม (กฎ free-first: decision 382ecd50)
งานนี้ต่อจากทางเข้าเสียงและภาษาธรรมชาติที่ทำเสร็จแล้ว ซึ่งใช้ Whisper ถอดเสียง และตั้ง `message.voice = true`

## เป้าหมาย
- ผู้ใช้พูดมา → ได้ข้อความเสียง (audio) 1 ข้อความ ตามด้วยข้อความเดิมของบริการ ทั้งหมดอยู่ใน reply เดียว
- เสียงสั้น ไม่เกินราว 2–3 ประโยค (≈20 วินาที) ถ้าตัดให้สั้นลง ให้ปิดท้ายว่า "รายละเอียดอ่านในข้อความได้เลยครับ"
- ใช้ edge-tts (ฟรี) เป็นหลัก สลับไป Paxa ได้ด้วยตัวแปร env หรือพารามิเตอร์ของคำขอ
- รอบแรกใส่เสียงให้ 4 จุด: (0) ข้อความ "ฟังเสียงไม่ชัด" ใน router (ใช้ทดสอบก่อน) (1) กฎหมาย (2) ธรรมะ/ปรึกษาชีวิต (3) แปลภาษา ซึ่งอ่านคำแปลด้วยเสียงของภาษาปลายทาง

## ไม่ทำ (รอบนี้)
- ไม่ตอบเป็นเสียงเมื่อผู้ใช้พิมพ์มา (เจ้าของเลือกแล้ว)
- ไม่ทำ LIFF / Mini App / WebSocket / WebRTC ทำเฉพาะ LINE OA
- ไม่มีตรรกะ "บัญชี VIP" เพราะยังไม่มีนิยามว่าใครคือ VIP มีแค่พารามิเตอร์ `provider` เตรียมไว้
- ไม่ใช้ AI เขียนคำตอบใหม่ ใช้กฎตายตัว (ฟรี เร็ว ทดสอบได้)
- ไม่ทำงานลบไฟล์เสียงเก่า (ไฟล์ละราว 100 KB ทำเมื่อพื้นที่เริ่มเยอะ)

## สิ่งที่ห้ามเกิด (anti-goals)
- **บอทเงียบ:** TTS ล้ม ช้าเกิน 8 วินาที หรือ Hermes ล่ม → ต้องส่งข้อความตามเดิม
- **ค่าใช้จ่ายงอก:** Paxa ถูกเรียกเฉพาะเมื่อ edge-tts ล้ม และมีการตั้ง key ไว้แล้ว หรือมีคำขอระบุ `provider: paxa`
- **เสียงยาวน่าเบื่อ** หรือมีเสียงอ่านสัญลักษณ์ ลิงก์ หรือตัวย่อ

## ข้อจำกัด (ตรวจแล้ว)
- **LINE audio:** ใช้ลิงก์ HTTPS เท่านั้น รองรับ "mp3 or m4a" ขนาดไม่เกิน 200 MB และต้องส่ง `duration` เป็นมิลลิวินาที (ที่มา: LINE Messaging API reference)
- **จำนวนข้อความ:** reply หนึ่งครั้งส่งได้ไม่เกิน 5 ข้อความ ถ้าบริการใช้ครบ 5 แล้ว ไม่ต้องใส่เสียง
- **reply token:** ใช้ได้ราว 1 นาที
- **edge-tts:** ใช้ช่องทาง Read Aloud ของ Edge ซึ่งไม่เป็นทางการ อาจโดนปิดได้
  - ส่ง SSML เองไม่ได้ ปรับได้แค่ `rate`, `pitch`, `volume`
  - ผลลัพธ์เป็น mp3 24kHz 48kbps → `duration_ms = จำนวนไบต์ / 6`
- **ที่รัน:** n8n รัน edge-tts ไม่ได้ เพราะเป็นไลบรารี Python และใช้ websocket
  - Hermes router (FastAPI) บน Render ใช้แผน starter ซึ่งไม่หลับ
  - Hermes ยืนยันตัวตนด้วย `current_user` (รองรับ API key ของ agent)
  - Hermes ใช้ Supabase `vgnauwwoqzdpunavbace`
- **Paxa (มีอยู่แล้ว ใช้กับคลิปสั้นและแปลภาษา):**
  - `POST https://api.paxalabs.com/v1/tts` header `x-api-key` model `paxa-tts-flash-v2` ขอ `format: mp3` ได้ (ค่าเริ่มต้นของ Paxa คือ mp3)
  - key ที่ใช้ได้อยู่ใน n8n credential `Header Auth account 6` (ตรวจแล้ว 2026-11-10) ส่วน credential `Paxa TTS` ใช้ไม่ได้
  - เสียง v2 พูดได้แค่ ไทย / อังกฤษ / จีน จึงสำรองให้ภาษาอื่นไม่ได้ ภาษาอื่นถ้า edge ล้มจะเป็นข้อความอย่างเดียว
  - ราคา 10 เครดิตต่อ 1000 ตัวอักษร (คำตอบเสียง 200 ตัวอักษร ≈ 2 เครดิต)
  - แผนฟรี: 10 คำขอต่อนาที ทำได้ทีละ 1 งาน ใช้ร่วมกับคลิป แปล และเอกสาร ถ้าระบบเต็มจะตอบเป็นข้อความอย่างเดียว
  - Hermes ต้องมี key ของตัวเองใน Render env `PAXA_API_KEY`
    - เจ้าของสร้าง key ใหม่ใน Paxa พร้อมกำหนดเพดานเครดิต (เหมือน key `voice` ที่จำกัด 3,000) แล้วใส่เองใน Render
    - ห้ามวาง key ในแชตหรือใน repo

## แนวทางที่พิจารณา
- **1 (เลือก): ตัวช่วยกลางใน n8n ชื่อ "ตอบพร้อมเสียง"** แต่ละบริการเปลี่ยนโหนดตอบ LINE มาเรียกตัวช่วยนี้ ถ้า TTS ล้มจะตอบเป็นข้อความเท่านั้น ข้อเสียคือต้องแก้ทีละบริการ
- 2: ให้ทุกคำตอบผ่าน Hermes ก่อนส่งถึง LINE ได้เสียงทุกบริการในครั้งเดียว แต่ถ้า Hermes ล่ม บอทจะเงียบทั้งระบบ ซึ่งชนกับข้อห้าม
- 3: ส่งเสียงตามหลังด้วย push ไม่ต้องแก้บริการ แต่กินโควตา push ซึ่งไม่ฟรี

## การออกแบบ

```
ผู้ใช้พูด ─► Router: ตรวจลายเซ็น → Whisper → message.voice = true → บริการ (กฎหมาย / ธรรมะ / แปล)
                                                              │ ได้ข้อความคำตอบ
                                                              ▼
                                    sub-workflow "ตอบพร้อมเสียง" {replyToken, messages, voice, lang, speakText?}
                                     ├─ voice ≠ true หรือ messages ≥ 5 ──► LINE reply (ข้อความเดิม)
                                     └─ voice = true ──► Hermes POST /tts  (timeout 8 วิ)
                                                          ├ to_spoken(): ข้อความ → ภาษาพูด
                                                          ├ edge-tts  (ล้ม → Paxa ถ้าตั้งไว้)
                                                          └ mp3 → Supabase Storage bucket "tts" (อ่านได้สาธารณะ)
                                                          ◄ {url, duration_ms, spoken_text, provider}
                                        สำเร็จ ─► LINE reply [audio, ...ข้อความเดิม]
                                        ล้ม/ช้า ─► LINE reply (ข้อความเดิม)
```

### 1. Hermes `POST /tts` (ไฟล์ใหม่ `tts.py` + route ใน `main.py`)
- **สิทธิ์ (ผู้สร้างเลือก):** `Depends(current_user)` และ user id ต้องอยู่ใน env `TTS_ALLOWED_USERS` (บอท n8n) ไม่งั้นตอบ 403
  - เหตุผล: `/auth/signup` เปิดให้ใครก็สมัครได้ และ Paxa เสียเงิน
- **จำกัดอัตรา (ผู้สร้างเลือก):** ต่อ user 30 ครั้งต่อนาที เก็บในหน่วยความจำ เพราะ rate limit เดิมคุมแค่ login/signup
  - ponytail: ถ้ามีหลาย instance ค่อยย้ายไปใช้ Redis ที่มีอยู่
- **ผู้เรียก:** n8n ใช้ credential เดิม "Hermes bot login" (`2n0MfzWuxgUw15zU` บอทตัวเดียวกับ embedder) → `POST /auth/login` → Bearer ไม่ต้องสร้างบัญชีใหม่
- **ข้อมูลเข้า:**
  - `text` (ไม่เกิน 2000 ตัวอักษร)
  - `lang` (ค่าเริ่มต้น `th`)
  - `voice?`
  - `provider?` (`edge` | `paxa`)
  - `spoken` (ค่าเริ่มต้น true ทำงานเฉพาะเมื่อ `lang = th`)
- **`spoken=false` (ใช้กับคำแปล):** ไม่แปลงเป็นภาษาพูด ไม่เติม ครับ/คำปิดท้าย และไม่ตัดกลางประโยค
  - ยาวเกิน 300 ตัวอักษร → 422 → n8n ตอบข้อความอย่างเดียว
  - ผู้สร้างเลือก: คำแปลที่ถูกตัดครึ่งแย่กว่าไม่มีเสียง
- **ผู้ให้บริการ (adapter):** ฟังก์ชัน `synthesize(text, voice) -> bytes` แยกตามผู้ให้บริการ
  - ลำดับคือ `provider` ในคำขอ → `TTS_PROVIDER` (ค่าเริ่มต้น `edge`) → ถ้าล้มให้ใช้ `paxa` เมื่อมี `PAXA_API_KEY`
- **เสียง:**
  - เสียงไทยมาจาก `TTS_VOICE_TH` (ค่าเริ่มต้น `th-TH-NiwatNeural` เสียงผู้ชาย ให้ตรงกับ "ครับ")
  - ภาษาอื่นใช้ตารางเสียง edge ตามรหัสภาษา 14 ภาษาที่บริการแปลรองรับ
- **ความเร็วเสียง:** `TTS_RATE` (ค่าเริ่มต้น `-5%`)
- **ไฟล์:**
  - path คือ `tts/<sha256(provider+voice+rate+spoken_text)[:32]>.mp3` ถ้าข้อความเดิมก็ใช้ไฟล์เดิม
  - อัปโหลดด้วย client ของผู้ใช้ (`db(user)`) แล้วคืน public URL
- **ข้อมูลออก:** `{url, duration_ms, spoken_text, provider}`
  - TTS ทุกตัวล้ม → 503
  - ข้อความว่างหลังทำเป็นภาษาพูด → 422

### 2. `to_spoken(text)` แปลงเป็นภาษาพูด (Python, มี pytest)
- **ตัดทิ้ง:**
  - markdown (`#` `*` `_` `` ` `` `>`)
  - หัวรายการ (`- ` `• ` `1.` ต้นบรรทัด)
  - URL, อีโมจิ, วงเล็บอ้างอิงแบบ `[1]`
- **เวลา:** `HH:MM` / `HH.MM น.` → ภาษาพูด
  - ตีหนึ่ง–ตีห้า · หกโมงเช้า–สิบเอ็ดโมงเช้า · เที่ยง · บ่ายโมง · บ่ายสองโมง–บ่ายสามโมง · สี่โมงเย็น–หกโมงเย็น · หนึ่งทุ่ม–ห้าทุ่ม · เที่ยงคืน
  - นาที: `30` → "ครึ่ง" นาทีอื่นต่อท้าย "… นาที" ถ้ามีนาทีให้ตัดคำ เช้า/เย็น ออก
  - ตัวอย่าง: `08:00` → แปดโมงเช้า · `12.30 น.` → เที่ยงครึ่ง · `14:15` → บ่ายสองโมงสิบห้านาที
- **ตัวย่อ:**
  - เดือน `พ.ย.` → พฤศจิกายน (ครบ 12 เดือน)
  - ต. → ตำบล · อ. → อำเภอ · จ. → จังหวัด (เฉพาะเมื่อตามด้วยชื่อ) · กม. → กิโลเมตร · ชม. → ชั่วโมง
- **ตัวเลขและสัญลักษณ์:** `1,250` → `1250` · `฿` → บาท
- **ความยาว:**
  - ตัดที่ช่องว่างหรือขึ้นบรรทัดใหม่ ให้ได้ไม่เกินราว 200 ตัวอักษร
  - ถ้าถูกตัด ต่อท้ายว่า "รายละเอียดอ่านในข้อความได้เลยครับ"
  - ถ้าไม่ได้ลงท้ายด้วย ครับ/ค่ะ/นะครับ ให้เติม "ครับ"
- **ช่วงหยุด:** ขึ้นบรรทัดใหม่หรือมีหลายช่องว่าง → ใช้ช่องว่างเดียว เพราะในภาษาไทย ช่องว่างคือช่วงหยุดสั้นอยู่แล้ว

## เคล็ดลับปรับเสียงไทยให้ลื่นหู
- **ความเร็ว:**
  - `rate` ค่าเริ่มต้น `-5%` สำหรับผู้ฟังทั่วไปในตำบล
  - `-10%` เหมาะกับคำตอบกฎหมายที่ประโยคยาว ไม่ควรเร็วเกิน `+5%`
- **pitch / volume:** คงไว้ที่ `+0Hz` / `+0%` ถ้าปรับ pitch เสียงไทยจะเพี้ยนวรรณยุกต์ง่าย
- **ช่วงหยุด:**
  - edge-tts ใส่ `<break>` ไม่ได้ ใช้ช่องว่างหรือจุลภาคแทน
  - ประโยคละหนึ่งเรื่อง ไม่เกินราว 40 ตัวอักษรต่อช่วง
- **ตัวเลขและตัวย่อ:** เขียนเวลาเป็นคำพูด ขยายตัวย่อเสมอ ตัวเลขเงินคงเป็นตัวเลขได้ (edge อ่าน 1250 ถูก)
- **Paxa:** ใช้ป้ายท่าทาง เช่น `[calm, friendly]` และช่วงหยุด `[pause 300ms]` ได้ ใช้เฉพาะเมื่อเลือก Paxa
