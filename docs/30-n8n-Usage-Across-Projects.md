# 30 — n8n ใช้ทำอะไรบ้างในโครงการทั้งหมด

> สถานะ: ใช้ **n8n Cloud** แบบจ่ายรายเดือนอยู่แล้ว (ไม่ต้องรีบย้ายไป self-host — ดูหัวข้อท้ายเอกสาร)
> เอกสารนี้ตอบคำถามเดียว: **งานไหนควรอยู่ใน n8n งานไหนไม่ควร**

---

## 1. หลักการตัดสิน — 3 ข้อ ใช้ได้ทุกโครงการ

เวลาไม่แน่ใจว่างานหนึ่งควรอยู่ใน n8n หรือควรเขียนเป็นโค้ด ให้ถาม 3 คำถามนี้

**ข้อ 1 — งานนี้แตะเงิน สิทธิ์ หรือข้อมูลส่วนบุคคลไหม**

ถ้าใช่ → **เขียนเป็นโค้ด** ไม่ใช่ n8n

เพราะงานพวกนี้ต้องมีร่องรอยตรวจสอบย้อนหลัง (audit trail) ที่พิสูจน์ได้ว่าใครทำอะไรเมื่อไหร่ และต้องมีชั้นตรวจสิทธิ์ระดับผู้ใช้ ซึ่ง n8n ไม่มี — workflow ใน n8n ทำงานด้วยสิทธิ์เดียวเสมอ (สิทธิ์ของ credential ที่ใส่ไว้) ไม่รู้จักว่า "ผู้ใช้คนนี้เห็นข้อมูลนี้ได้หรือไม่"

*(ตรงกับที่ตัดสินใจไว้แล้วสำหรับ สกป. — logic การเงินเป็น custom backend, n8n ใช้เฉพาะงานเสริมที่ไม่แตะเงิน)*

**ข้อ 2 — งานนี้เปลี่ยนบ่อยตามที่ผู้ใช้จริงขอไหม**

ถ้าใช่ → **n8n**

เพราะแก้ได้โดยไม่ต้อง deploy ใหม่ และคนที่ไม่ใช่โปรแกรมเมอร์ก็แก้เองได้ ข้อความแจ้งเตือน เวลาเตือน เงื่อนไขว่าจะเตือนใคร — พวกนี้จะถูกขอแก้เป็นสิบครั้งในเดือนแรกที่มีผู้ใช้จริง

**ข้อ 3 — ถ้า workflow นี้ตายไป 3 วันโดยไม่มีใครรู้ จะเสียหายแค่ไหน**

ถ้าคำตอบคือ "เสียหายหนัก" → อย่าฝากไว้กับ n8n อย่างเดียว

n8n ไม่บอกคุณเองเมื่อ workflow พัง มันเงียบ (ดูหัวข้อกับดัก ข้อ 1)

**สรุปเป็นประโยคเดียว: n8n คือ *กาว* ไม่ใช่ *แกน***

---

## 2. แยกรายโครงการ

### 2.1 Delivery ระดับตำบล — ลำดับ 2

| ให้ n8n ทำ | ห้ามให้ n8n ทำ |
|---|---|
| ออร์เดอร์ใหม่เข้า → แจ้งกลุ่ม LINE ไรเดอร์ | สร้าง/แก้ออร์เดอร์ |
| ไม่มีไรเดอร์รับใน 5 นาที → เตือนตัวแทนตำบล | จับคู่ไรเดอร์กับงาน |
| สมาชิกใหม่รออนุมัติ → แจ้งตัวแทนตำบล | คิดค่าส่ง |
| สรุปยอด/จำนวนออร์เดอร์รายวัน ส่งเข้าแชท | ตัดเงิน ยืนยันสลิป |
| ซิงก์ข้อมูลไป Google Sheets ให้ตัวแทนตำบลดูโดยไม่ต้องเข้าหลังบ้าน | ให้/ถอนสิทธิ์สมาชิก |

**วิธีต่อ:** Supabase มี Database Webhooks — ตั้งว่า "มีแถวใหม่ใน `orders` → ยิงไปที่ URL นี้" ชี้ไปที่ Webhook node ของ n8n **ไม่ต้องแก้โค้ดแอปเลยแม้แต่บรรทัดเดียว**

---

### 2.2 LINE OA ถาม-ตอบพุทธศาสนา (RAG) — ลำดับ 1 คุ้มที่สุด

**นี่เป็นโครงการเดียวที่ n8n ควรเป็น *แกน* ไม่ใช่แค่กาว**

เพราะเข้าเกณฑ์ครบ: ไม่แตะเงิน · ไม่มีระบบสิทธิ์ซับซ้อน (ใครถามก็ได้) · และ prompt กับลำดับขั้นตอนต้องปรับบ่อยมากในช่วงแรก ซึ่งเป็นงานที่ต้องลองแล้วดูผลทีละรอบ — อยู่ใน n8n จะเร็วกว่าเขียนโค้ดหลายเท่า

**pipeline ที่ทำได้ทั้งหมดใน n8n:**

```
Webhook (รับข้อความจาก LINE)
  → ตรวจ x-line-signature
  → แปลงคำถามเป็น embedding
  → ค้น Supabase pgvector หา chunk ที่ใกล้เคียง
  → ส่งคำถาม + chunk ให้ LLM
  → ★ ตรวจว่าคำตอบอ้างอิงตรงกับต้นฉบับจริง ★
  → ตอบกลับทาง LINE พร้อมอ้างอิง
```

**ขั้นตอนที่มีดาว คือหัวใจของโครงการนี้** — สิ่งที่คุณต้องการคือคำตอบที่**อ้างอิงได้จริง** ไม่ใช่คำตอบที่ฟังดูดี ดังนั้นต้องมี node แยกที่เอาข้อความอ้างอิงในคำตอบไปเทียบกับ chunk ต้นทางก่อนส่งออก ถ้าเทียบไม่ตรงให้ตอบว่า "ไม่พบในเอกสารที่มี" แทนที่จะเดา

ถ้าไม่มีชั้นนี้ ระบบจะสร้างพุทธพจน์ปลอมออกมาโดยที่ดูน่าเชื่อถือ ซึ่งอันตรายกว่าไม่มีระบบเลย

---

### 2.3 academy.html + admin.html — ลำดับ 3 (ต่อยอดของที่มีอยู่)

**ใช้อยู่แล้ว:** Human-in-the-Loop อนุมัติเนื้อหาผ่าน LINE OA (admin.html → `content_approvals` → n8n → ปุ่มอนุมัติใน LINE → Edge Function)

**เพิ่มได้อีก:**

- มีคนซื้อคอร์ส → แจ้งเข้าแชท + ส่งข้อความต้อนรับผู้เรียน
- ซื้อแล้วไม่เข้าเรียนภายใน 7 วัน → ส่งข้อความเตือน
- เรียนจบ → ออกใบประกาศอัตโนมัติ ส่งเข้า LINE
- คนกรอกฟอร์มสนใจแต่ยังไม่ซื้อ → ส่ง follow-up ตามลำดับ

**ห้าม:** ตรวจสถานะการชำระเงินจริง และให้สิทธิ์เข้าคอร์ส — สองอย่างนี้ต้องอยู่ใน Edge Function ที่ยืนยันกับ Omise โดยตรง n8n รับรู้ได้ แต่ห้ามเป็นคนตัดสิน

---

### 2.4 สกป. / สถาบันการเงินประชาชน — ลำดับ 4

**ให้ n8n ทำ:** เตือนงวดชำระใกล้ครบ · แจ้งคำขอกู้ใหม่รออนุมัติ · รายงานสรุปรายเดือนส่งคณะกรรมการ · ส่งออกรายงานเป็นไฟล์ตามรอบ

**ห้ามเด็ดขาด:** บันทึกรายการเงิน · คำนวณดอกเบี้ย · อนุมัติกู้ · ปรับยอดหุ้น

ข้อนี้เคยตัดสินใจไว้แล้วและยังถูกต้องอยู่ — ระบบการเงินที่มีกฎหมายรองรับ (พ.ร.บ. 2562) ต้องพิสูจน์ตัวเลขย้อนหลังได้ทุกรายการ ถ้ายอดเงินเคยผ่าน n8n แล้ววันหนึ่งตัวเลขไม่ตรง จะไล่ไม่ได้ว่าผิดตรงไหน

---

### 2.5 เหรียญคุณธรรม — ลำดับ 5

**ให้ n8n ทำ:** รับฟอร์มลงชื่อสนับสนุน → แจ้งทีม + เพิ่มขึ้น honor board · เตือนคณะกรรมการตำบลเมื่อถึงรอบ reconcile รายเดือน · รวบรวมรูป GPS จากอาสาสมัครเข้าคิวรอตรวจ · ดึงข้อมูลภาพถ่ายดาวเทียมตามรอบ

**ห้าม:** ออกเหรียญ (ต้องผ่าน multi-sig 2-of-3 ตามที่ออกแบบไว้) · ตัดสินว่าการปลูกผ่านการตรวจสอบหรือไม่ (ต้องเป็นคน)

---

### 2.6 ebooks + แผนการตลาด 4 เล่ม — ลำดับ 6

ตั้งเวลาโพสต์ · รวมยอดขายจากหลายช่องทางมาไว้ที่เดียว · ตอบอัตโนมัติคนที่ทักถามซื้อ · ส่งไฟล์ให้ลูกค้าหลังยืนยันการชำระเงิน

งานนี้ n8n ทำได้ดีและเสี่ยงต่ำ แต่ผลตอบแทนต่อเวลาที่ลงไปน้อยกว่าข้อ 2.2 มาก จึงอยู่ท้าย ๆ

---

### 2.7 งานเอกสารและนโยบาย (พ.ร.บ.คณะสงฆ์, anti-corruption, SE company) — แทบไม่ต้องใช้

ใช้ได้แค่ backup เอกสารข้าม Drive/Supabase อัตโนมัติ และเตือนกำหนดส่ง

**งานเขียนเอกสารนโยบายเป็นงานที่ต้องใช้วิจารณญาณ อย่าพยายาม automate** — จะได้เอกสารที่ดูเหมือนเสร็จแต่ใช้จริงไม่ได้

---

## 3. งานฐานราก — ทำครั้งเดียว ใช้ได้ทุกโครงการ

ทำ 3 อย่างนี้ **ก่อน** สร้าง workflow จริงตัวแรก ไม่งั้นจะต้องกลับมารื้อทีหลัง

1. **Sub-workflow "ส่งข้อความ LINE"** ตัวเดียว — ทุก workflow เรียกใช้ตัวนี้ เวลาเปลี่ยน token หรือเปลี่ยนรูปแบบข้อความ แก้ที่เดียว
2. **Sub-workflow "แจ้ง error"** — ตั้ง Error Trigger ในทุก workflow ให้ชี้มาที่นี่ แล้วส่งเข้า Telegram ทีมงาน
3. **ตาราง log กลางใน Supabase** — ให้ n8n เขียนบันทึกว่าทำอะไรไปเมื่อไหร่ สำเร็จหรือไม่ เพื่อให้ตรวจสอบย้อนหลังได้โดยไม่ต้องเปิด n8n

---

## 4. กับดัก 5 ข้อ ที่ต้องกันไว้ตั้งแต่วันแรก

**1. workflow ตายเงียบ** — n8n ไม่แจ้งคุณเองเมื่อ workflow พัง มันหยุดทำงานเฉย ๆ ระบบแจ้งเตือนไรเดอร์อาจตายไปสามวันโดยไม่มีใครรู้ **แก้:** Error Trigger ทุกตัว ไม่มีข้อยกเว้น

**2. credential กระจัดกระจาย** — เก็บ token ใน n8n Credentials เท่านั้น **ห้าม hardcode ลงใน HTTP Request node** เพราะ token จะติดไปกับ workflow ตอน export และหลุดได้ง่าย

**3. webhook URL เปลี่ยนตอนย้าย host** — ถ้าวันหนึ่งย้ายจาก Cloud ไป VPS ทุกที่ที่ชี้มาหา n8n ต้องแก้ตาม (Supabase webhook, LINE webhook, Omise webhook) ลืมข้อนี้แล้วระบบจะเงียบโดยไม่มี error ให้เห็น → **จดรายการปลายทางทั้งหมดไว้ตั้งแต่แรก**

**4. execution quota หมดเร็วกว่าที่คิด** — งานที่ใช้ Schedule Trigger ยิงถี่ ๆ (เช่นทุกนาที) กินโควตาเดือนละหลายหมื่นครั้งโดยไม่ได้ทำอะไรเลย **ใช้ webhook แทน polling เสมอ** ยกเว้นกรณีที่ปลายทางส่ง webhook ไม่ได้จริง ๆ

**5. ข้อมูลส่วนบุคคลไหลผ่าน n8n** — เบอร์โทรและที่อยู่ลูกค้าจะวิ่งผ่าน workflow และถูกเก็บไว้ใน execution log ของ n8n **ส่งเฉพาะ field ที่จำเป็น อย่าส่งทั้งแถว** และตั้งอายุการเก็บ execution log ให้สั้น — เรื่องนี้อยู่ใต้ PDPA และโครงการเหรียญคุณธรรมก็มีข้อกำหนด PDPA ระบุไว้แล้ว

---

## 5. ลำดับที่ควรลงมือ

1. **งานฐานราก 3 อย่าง** (หัวข้อ 3) — ครึ่งวัน
2. **LINE OA ถาม-ตอบพุทธศาสนา** — คุ้มค่าที่สุด และเป็นโครงการที่ n8n เหมาะที่สุด
3. **แจ้งเตือน Delivery** — รอให้ระบบหลักใช้งานได้ก่อน (ตอนนี้ยังติด login ด้วยเบอร์)
4. **ต่อยอด academy** — ของมีอยู่แล้ว เพิ่มทีละอย่างได้เรื่อย ๆ
5. เหรียญคุณธรรม / สกป. / ebooks — เมื่อโครงการเดินถึงจุดที่มีคนใช้จริง

---

## 6. เรื่อง self-host (Hostinger) — ยังไม่ต้องรีบ

workflow ของ n8n **export เป็น JSON ได้** ไม่มี vendor lock-in ย้ายวันไหนก็ได้ ต้นทุนของการรอจึงเกือบเป็นศูนย์

**ย้ายเมื่อเจอสัญญาณข้อใดข้อหนึ่ง:**

- ใช้ execution เกินครึ่งของ quota เป็นประจำ (ดูหน้า Usage)
- ต้องใช้ community node ที่ไม่อยู่ในรายการ verified — *แต่ข้อนี้เลี่ยงได้เกือบทุกกรณีด้วย `HTTP Request` node*
- ค่ารายเดือนสูงกว่าค่า VPS **บวกค่าแรงดูแล** อย่างมีนัยสำคัญ

**สิ่งที่ต้องนับเพิ่มถ้าย้าย:** อัปเดตเวอร์ชันเอง · ตั้ง backup และเคยทดสอบ restore จริง · SSL/โดเมน/reverse proxy · และข้อสำคัญที่สุด — **ล่มตอนตีสองไม่มีใครกู้ให้**

สำหรับระบบที่ไรเดอร์ต้องพึ่งทุกวัน ข้อสุดท้ายมีน้ำหนักมากกว่าส่วนต่างค่าเช่าเซิร์ฟเวอร์
