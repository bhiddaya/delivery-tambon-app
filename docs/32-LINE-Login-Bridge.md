## ลำดับการทำงาน

1. ผู้ใช้กด **เข้าสู่ระบบด้วย LINE** → LIFF พาไปยืนยันตัวตนกับ LINE
2. หน้าเว็บได้ **ID token** กลับมา แล้วส่งไปที่ Edge Function `line-login`
3. Edge Function ส่ง token ต่อให้ LINE ตรวจที่ `/oauth2/v2.1/verify`
   — LINE ตรวจลายเซ็น วันหมดอายุ และ `aud` ให้ครบในคำขอเดียว
   เราจึงไม่ต้องดึงกุญแจสาธารณะมา verify เองให้เสี่ยงพลาด
4. หาบัญชี ตามลำดับนี้
   - `profiles.line_user_id` ตรงกันไหม → **ใช่ก็เข้าบัญชีเดิม**
   - ไม่เจอ ค่อยดูอีเมลแฝง `<lineUserId>@line.invalid`
   - ไม่เจออีก → สร้างบัญชีใหม่
5. ออก `token_hash` ของ magic link (ไม่มีการส่งอีเมลจริง) ส่งกลับให้เบราว์เซอร์
6. เบราว์เซอร์เรียก `verifyOtp()` แลกเป็น session จริง
7. มีโปรไฟล์แล้ว → ไปหน้าตามบทบาท / ยังไม่มี → ไป `/onboarding`

## จุดออกแบบที่ตั้งใจ

**เบราว์เซอร์ไม่เคยเห็น secret key** — การสร้าง/ค้นผู้ใช้ใน auth ต้องใช้สิทธิ์ระดับ
service ซึ่งห้ามอยู่ในหน้าเว็บเด็ดขาด เบราว์เซอร์จึงส่งได้แค่ ID token
แล้วให้ฝั่งเซิร์ฟเวอร์เป็นคนตัดสินว่าจะออก session ให้หรือไม่

**ค้น `line_user_id` ก่อนอีเมลแฝง** — คนที่สมัครด้วยเบอร์ไว้ก่อนแล้วมาผูก LINE
ทีหลัง จะเข้า **บัญชีเดิม** ไม่ใช่ได้บัญชีที่สองที่ประวัติออร์เดอร์หายหมด

**ปุ่มหายไปเงียบ ๆ ถ้าใช้ไม่ได้** — ยังไม่ได้ตั้ง `NEXT_PUBLIC_LIFF_ID`
หรือ LIFF init ไม่ผ่าน ปุ่มจะไม่ขึ้นเลย ดีกว่าโชว์ปุ่มที่กดแล้วไม่มีอะไรเกิดขึ้น

**`verify_jwt = false`** — ตอนเรียกฟังก์ชันนี้ผู้ใช้ยังไม่มี session
นั่นคือสิ่งที่กำลังจะขอ การยืนยันตัวตนของ endpoint นี้คือ
"ID token ต้องผ่านการตรวจของ LINE" ซึ่งปลอมไม่ได้

## สถานะ

**ขึ้น production แล้ว** — ปุ่ม "เข้าสู่ระบบด้วย LINE" สีเขียวแสดงอยู่ที่

`createUser` / `generateLink` ของ GoTrue (คนละบริการกับที่ probe ทดสอบ)
จะทำงานผ่าน key ตัวนี้จริงไหม **ต้องกดจากในแอป LINE หนึ่งครั้งถึงจะรู้**

## ที่ยังค้าง

- **ทดสอบล็อกอินด้วย LINE จริงจากมือถือ** ← ขั้นถัดไปที่สำคัญที่สุด
- `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` ยังไม่ได้ใส่ใน Vercel
  (ใช้กับ webhook และการส่งข้อความ ไม่เกี่ยวกับการล็อกอิน) —
  **ควรกด Issue ใหม่ทั้งคู่ก่อน** เพราะค่าเดิมเคยแสดงออกมาในหน้าจอระหว่างทำงาน
- `src/lib/types.ts` ยังไม่ตรงกับฐานข้อมูลจริง: DB มี `order_type: agri_service`,
  `vehicle_type` เพิ่ม harvester / rice_transplanter / drone / car และตาราง
  `plots` `job_seekers` `places` `web_applications` ที่ไฟล์ types ยังไม่รู้จัก
  (sync ทั้งไฟล์เมื่อไหร่ ต้องตั้งชื่อภาษาไทยของบริการเกษตรใน UI ด้วย)
- `git push` จากเครื่องยังถูกบล็อกที่ proxy — ตอนนี้ต้องอัปโหลดผ่านหน้าเว็บ
  GitHub ทีละโฟลเดอร์ (รอบล่าสุดใช้ 9 รอบ) ถ้าแก้เรื่อง repo authorization ได้
  จะประหยัดเวลาไปมาก
