# ระบบผู้แนะนำ (ส่วนแบ่งรายได้ 30/40/30)

กติกาฉบับเต็ม: `bavorn-ai-dashboard/docs/referral-revenue-share-draft.md` (เจ้าของตัดสิน 21 ต.ค. 2569)
สถานะ: โค้ดพร้อมให้ตรวจ ยังไม่ได้ติดตั้ง migration บนฐานจริง · ไม่โอนเงินจริง · ไม่ส่ง LINE

## ทำงานอย่างไร

1. **ขอลิงก์:** สมาชิกที่อนุมัติแล้วและผูก LINE แล้วเปิด `https://liff.line.me/<LIFF_ID>/liff/referral`
   ระบบออกรหัส 6 ตัวให้ครั้งแรก แสดงลิงก์ + QR (ดาวน์โหลด/คัดลอก) และยอดของตัวเอง
2. **คนใหม่เปิดลิงก์** `/liff/ref?c=CODE` → ล็อกอิน LINE → `referral_claim` ผูก LINE userId กับผู้แนะนำ
   - ผู้แนะนำคนแรกเท่านั้น เปลี่ยนไม่ได้ · ชวนตัวเองไม่ได้ · สมาชิกที่อนุมัติแล้วผูกย้อนหลังไม่ได้
   - ผูกกับ "คน" ไม่ใช่บทบาท: คนเดียวกันเป็นทั้งผู้ซื้อและร้านได้ ใช้ผู้แนะนำคนเดียวกัน
   - จากนั้นกดสมัครลูกค้า / ร้านค้า / ไรเดอร์ ตามปกติ (ฟอร์ม n8n เดิมผูกด้วย LINE userId อยู่แล้ว ไม่ต้องแก้ฟอร์ม)
   - ชื่อผู้แนะนำที่พิมพ์เองในฟอร์ม (`profiles.referrer_first_name/last_name`) ใช้อ้างอิงเท่านั้น
3. **เริ่มนับสิทธิ์** เมื่อโปรไฟล์ของคนที่ถูกแนะนำได้รับอนุมัติ (trigger `profiles_referral_start`) อายุ 12 เดือน
4. **คำนวณรายเดือน** (`referral_month_rows`) ต่อออเดอร์ที่: ส่งสำเร็จ · ลูกค้าจ่ายแล้ว · ไม่ใช่ `is_test`/`is_drill` · ไม่มี `order_refunds` · มีค่าสินค้า
   - ค่า GP = ค่าสินค้า × `gp_pct` ของตำบล
   - หัก admin + ระบบ + ส่วนแบ่งตัวแทน (`tambons.agent_share_commission_pct`) + ค่าโอน/ภาษี + สำรอง (ทั้งหมดเป็น % ของค่า GP)
   - ผู้แนะนำร้าน 30% · ผู้แนะนำผู้ซื้อ 40% ของค่า GP สุทธิ · ไม่มีผู้แนะนำ/หมดสิทธิ์/ถูกตัดสิทธิ์ → เข้า บวร
   - เดือนนับตามเวลาไทยของวันส่งสำเร็จ · ตำบลที่ยังไม่ตั้งอัตราไม่นับ · ก่อน `starts_on` ไม่นับ
5. **ปิดยอด** (ส่วนกลาง หน้า `/admin/referrals`) หลังเดือนจบ → บันทึก `referral_earnings` รายออเดอร์
   และสร้าง `referral_payouts` ให้ผู้ที่ยอดสะสมยังไม่จ่าย ≥ 100 บาท (ต่ำกว่านั้นยกไปเดือนถัดไป)
6. **ตัดสิทธิ์** (`referral_ban`) → ไม่ได้ยอดใหม่ ระงับรายการที่ยังไม่จ่าย

ใครเห็นอะไร: ผู้แนะนำเห็นของตัวเอง (`referral_me`) · ตัวแทนตำบลเห็นตำบลที่ดูแล · ส่วนกลางเห็นทั้งหมด ตั้งอัตรา ปิดยอด ตัดสิทธิ์
ตารางทั้งหมดเปิด RLS ไม่มี policy อ่านได้ผ่านฟังก์ชันเท่านั้น

## ต้องทำเพิ่มเมื่อเจ้าของอนุมัติ

- เพิ่มปุ่มเมนู LINE (rich menu) "ลิงก์แนะนำของฉัน" → `https://liff.line.me/<LIFF_ID>/liff/referral`
  (ถ้าต้องการให้พิมพ์ "ลิงก์แนะนำ" ในแชตได้ ให้บอทตอบปุ่ม URI ไปลิงก์เดียวกัน)
- ตั้งอัตรารายตำบลที่หน้า `/admin/referrals`

## ยังไม่ได้ทำ (ตั้งใจ)

- การจ่ายเงินจริง/บันทึกว่าจ่ายแล้ว (`referral_payouts.paid_at`) และหักภาษี ณ ที่จ่าย
- การต่ออายุครบ 12 เดือน (ตัวแทนเสนอ ส่วนกลางอนุมัติ) — ครั้งแรกเกิดหลังเปิดตัว 12 เดือน
- ส่วนแบ่งจากค่าส่ง/ค่าโดยสาร (กติกานับเฉพาะค่า GP จากยอดขายของผู้ขาย) → ไรเดอร์ผูกได้แต่ยังไม่มียอด
